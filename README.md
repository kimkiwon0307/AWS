# AWS

<details>
<summary><h2>1장. AWS란?</h2></summary>

> **개요:** 전통적인 인프라(온프레미스)와 클라우드 컴퓨팅의 차이를 이해하고, AWS의 핵심 서비스와 인프라 구조를 학습합니다.

---

### 1.1 클라우드 컴퓨팅
* **정의:** 물리 서버를 직접 구축하는 대신, 인터넷망을 통해 IT 자원(서버, 스토리지 등)을 필요한 만큼 빌려 쓰고 비용을 지불하는 서비스입니다.
* **핵심 이점:** 초기 비용 절감, 빠른 구축 속도, 유연한 확장성(Auto Scaling), 글로벌 배포 용이성.

#### 클라우드 서비스 유형 (공급사 관리 범위)
* **IaaS (인프라 제공):** 가상 하드웨어 자원 대여 (예: EC2, VPC). 엔지니어가 직접 OS/환경 제어 가능.
* **PaaS (플랫폼 제공):** 인프라+OS+런타임 관리. 개발자는 코드만 업로드 (예: Elastic Beanstalk, Lambda).
* **SaaS (소프트웨어 제공):** 최종 애플리케이션 형태 제공 (예: Gmail, Notion, Slack).

#### 클라우드 구축 모델
* **퍼블릭:** 불특정 다수 대상 서비스 (AWS, Azure 등).
* **프라이빗:** 특정 기업만을 위한 독점 인프라 (금융, 공공기관).
* **하이브리드:** 온프레미스와 퍼블릭 클라우드를 연동하는 실무 표준 방식.

---

### 1.2 AWS 서비스 개요
* **소개:** 세계 1위 클라우드 플랫폼. 강력한 CLI/API 지원 및 DevOps 친화적 환경 제공.

#### 10대 핵심 서비스
1. **EC2:** 가상 서버 대여
2. **S3:** 대규모 데이터 객체 스토리지
3. **RDS:** 관리형 관계형 DB
4. **VPC:** 가상 네트워크 망
5. **IAM:** 사용자 및 권한 제어
6. **Route 53:** 글로벌 DNS
7. **ELB:** 트래픽 로드 밸런싱
8. **CloudWatch:** 통합 모니터링
9. **Lambda:** 서버리스 컴퓨팅
10. **Auto Scaling:** 서버 자동 확장

#### 과금 원칙
* **종량제(Pay-As-You-Go):** 실제 사용한 만큼만 초/분/시간 단위 결제.
* **Tip:** 미사용 시 중지(Stop) 또는 종료(Terminate) 필수.

---

### 1.3 AWS 글로벌 인프라
* **리전 (Region):** 서비스 제공을 위한 지리적 허브 구역 (예: 서울 리전). 사용자 근접성에 따라 선택.
* **가용 영역 (AZ, Availability Zone):** 독립된 전력/네트워크를 갖춘 물리 데이터 센터 세트. 고가용성(HA)을 위해 여러 AZ에 서비스를 분산 배치.
</details>

<details>
<summary><h2>🍊 2장. AWS 컴퓨팅 서비스</h2></summary>

> **개요:** 클라우드 컴퓨팅의 개념을 이해하고, AWS의 핵심 서비스인 EC2를 중심으로 서버 배포, 관리, 모니터링 및 운영 실습을 학습합니다.

---

### 2.1 AWS 컴퓨팅 서비스 개요
* **정의:** 데이터를 처리하고 프로그램을 실행하는 능력. (CPU, Memory, Storage, Network)
* **패러다임:** 온프레미스(직접 구축)에서 클라우드(필요한 만큼 빌려 사용)로 전환.

#### 핵심 서비스 라인업
1. **Amazon EC2:** 가상 서버 생성 및 운영 (웹/API/DB 서버 등)
2. **AWS Lambda:** 코드만 업로드하여 실행하는 서버리스 서비스 (이벤트 기반)
3. **Amazon ECS:** 도커(Docker) 컨테이너 실행 및 관리
4. **Amazon EKS:** 쿠버네티스(Kubernetes) 관리형 환경
5. **Elastic Beanstalk:** 인프라 구성 자동 배포 플랫폼

---

### 2.2 Amazon EC2 (Elastic Compute Cloud)
* **인스턴스 상태:** Running(실행), Stopped(정지), Rebooting(재부팅), Terminated(삭제).
* **AMI (Amazon Machine Image):** OS 설치 이미지 (윈도우 설치 USB와 같은 역할).
* **EBS (Elastic Block Store):** EC2용 가상 SSD/HDD 스토리지. (인스턴스 종료 시 삭제되지 않도록 주의)
* **네트워크:** 사설 IP(내부 통신), 공인 IP(외부 접속), VPC(격리된 네트워크).
* **보안 그룹:** 인스턴스 앞단의 가상 방화벽.

#### 인스턴스 구입 옵션
| 옵션 | 특징 | 적합한 환경 |
| :--- | :--- | :--- |
| **온디맨드** | 사용한 만큼 초 단위 과금 | 표준, 테스트 |
| **예약 인스턴스** | 1~3년 약정 할인 | 장기 구동 서버 |
| **스팟 인스턴스** | 최대 90% 저렴한 경매 방식 | 강제 종료 가능, 비용 절감 |

---

### 2.3 실습: EC2 배포 및 운영
1. **배포:** AMI 선택 ➔ 인스턴스 생성.
2. **접속:** `ssh -i my-key.pem ec2-user@공인IP`.
3. **Nginx 설치:** `sudo dnf install -y nginx` ➔ `sudo systemctl start nginx`.
4. **모니터링:** CloudWatch 활용 (CPU/네트워크 지표 확인).

#### 주요 리눅스 확인 명령어
* `top`: CPU/프로세스 확인
* `free -h`: 메모리 사용량 확인
* `df -h`: 디스크 용량 확인
* `ip addr` / `curl ifconfig.me`: 내부/외부 IP 확인
* `lsblk`: 디스크 구조 확인

#### ⚠️ 자원 정리 (실습 후 필수)
EC2 종료(Terminate) 후, 연결된 EBS 볼륨, Elastic IP(주소 릴리스), 스냅샷, 보안 그룹을 모두 삭제하여 불필요한 과금을 방지하세요.
</details>
   

<details>
<summary><h2>3장. AWS 네트워킹 서비스</h2></summary>

> **개요:** AWS 클라우드 환경에서 안전하고 확장성 있는 네트워크(VPC)를 구성하고, 서브넷 설계 및 통신 방법을 학습합니다.

---

### 3.1 네트워킹 핵심 요소
* **정의:** 여러 장치가 데이터를 주고받을 수 있도록 연결하는 것.
* **주요 서비스 매핑:**

| 온프레미스 개념 | AWS 서비스 / 기능 |
| :--- | :--- |
| **IP 주소** | Private / Public IP |
| **라우터 (L3)** | Route Table (라우팅 테이블) |
| **DNS** | Amazon Route 53 |
| **게이트웨이** | Internet Gateway |
| **NAT** | NAT Gateway |
| **방화벽** | Security Group / NACL |

---

### 3.2 AWS 글로벌 네트워크
* **리전(Region):** 데이터 센터가 밀집된 지리적 허브.
* **가용 영역(AZ):** 독립된 전력/냉각/네트워크를 갖춘 물리 데이터 센터 세트. (고가용성 확보를 위해 여러 AZ에 분산 배치)
* **글로벌 네트워크:** AWS 전용 사설 광케이블망으로 연결되어 보안성과 속도가 뛰어남.
* **엣지 로케이션(Edge/POP):** 사용자 근접지에서 콘텐츠를 빠르게 캐싱/전송하는 거점. (CloudFront, Route 53 등 활용)

---

### 3.3 Amazon VPC (Virtual Private Cloud)
* **VPC:** 논리적으로 격리된 가상 네트워크 공간.
* **주요 구성 요소:**
    * **Subnet:** 용도별(Public/Private)로 나눈 세부 네트워크 영역.
    * **Route Table:** 패킷 이동 경로를 안내하는 이정표.
    * **Internet Gateway:** 외부 인터넷과 통신하기 위한 출입구.
    * **NAT Gateway:** 사설 서브넷 서버의 외부 통신을 돕는 중계 장치.
    * **Security Group:** 인스턴스 단위 방화벽 (Stateful).
    * **NACL:** 서브넷 단위 방화벽 (Stateless).
* **외부 연결:** VPC Peering, VPN, Direct Connect(전용선), Transit Gateway 등.

---

### 3.4 실습: VPC 퍼블릭/프라이빗 구성 및 삭제
#### 아키텍처 목표
* **Public Subnet:** 외부 통신 가능 (웹 서버 배치)
* **Private Subnet:** 외부 접근 차단 (DB, 내부 WAS 배치)

#### [비교] 서브넷 특징
| 관리 항목 | 퍼블릭 서브넷 | 프라이빗 서브넷 |
| :--- | :--- | :--- |
| **공인 IP** | 사용 가능 | 사용 안 함 |
| **인터넷 통신** | 직접 가능 | NAT Gateway 필요 |
| **외부 접근** | 인바운드 허용 | 원천 차단 |

#### ⚠️ 자원 삭제 순서 (중요!)
불필요한 비용 발생 방지를 위해 반드시 역순으로 삭제합니다.
1. **EC2 종료**
2. **인터넷 게이트웨이** (분리 후 삭제)
3. **라우팅 테이블** 삭제
4. **서브넷** 삭제
5. **VPC** 삭제
6. **탄력적 IP(Elastic IP)** 릴리스 (고정 IP 과금 방지)

<summary><h2>4장. AWS 부하분산 서비스</h2></summary>

> **개요:** 트래픽 급증 시 서비스 안정성을 유지하기 위한 부하분산(Load Balancing) 기술과 AWS의 ELB 서비스 라인업을 학습합니다.

---

### 4.1 Amazon ELB (Elastic Load Balancer)

* **부하분산(Load Balancing):** 집중되는 트래픽을 여러 서버로 나누어 처리하여 성능 향상 및 고가용성(HA)을 확보하는 기술.
* **주요 기능:**
    * **트래픽 분산:** EC2, 컨테이너 등으로 자동 분산.
    * **Health Check:** 비정상 서버 감지 및 제외.
    * **SSL 종료:** HTTPS 복호화 처리로 백엔드 부담 완화.
    * **Auto Scaling 연동:** 인프라 증감 시 자동 등록/해제.

#### 핵심 구성 요소
1. **Listener:** 요청을 받을 포트와 프로토콜 정의 (HTTP 80, HTTPS 443 등).
2. **Target Group:** 트래픽을 받을 서버(대상)들의 집합.
3. **Health Check:** 서버 정상 작동 여부 주기적 확인 (200 OK 응답 체크).

#### ELB 종류
| 종류 | 계층 | 프로토콜 | 특징 |
| :--- | :--- | :--- | :--- |
| **ALB** | 7계층 | HTTP/HTTPS | 지능적 라우팅 (URL 경로, 헤더 기반) |
| **NLB** | 4계층 | TCP/UDP | 고성능, 대용량 트래픽, 고정 IP |
| **GWLB** | 3계층 | IP | 보안 장비 연결용 |
| **CLB** | - | HTTP/TCP | 레거시 (이전 세대) |

---

### 🛠️ 실무 표준 아키텍처
실제 서비스 운영 시 가장 많이 사용하는 표준 구조입니다.

```text
  Internet
     ↓
    ALB
     ↓
  Auto Scaling
     ↓
    EC2
     ↓
    RDS
```

<summary><h2>5장. AWS 스토리지 서비스 상세 정리</h2></summary>

> **개요:** 데이터의 성격과 활용 목적(OS, 공유, 백업 등)에 따라 적합한 스토리지(EBS, EFS, S3)를 선택하고 운영하는 방법을 학습합니다.

---

### 5.1 스토리지 유형 개요

| 유형 | 대표 서비스 | 비유 | 주요 특징 |
| :--- | :--- | :--- | :--- |
| **블록(Block)** | **Amazon EBS** | 하드디스크/SSD | EC2 인스턴스 전용 디스크, OS 설치 및 고성능 DB용 |
| **파일(File)** | **Amazon EFS** | 네트워크 공유 폴더 | 여러 EC2 인스턴스가 동시에 파일 공유 |
| **객체(Object)** | **Amazon S3** | 클라우드 드라이브 | 무제한 용량, 정적 웹 호스팅 및 대규모 데이터 저장 |

---

### 5.2 스토리지 선택 가이드 (Cheat Sheet)

| 상황 | 추천 서비스 | 이유 |
| :--- | :--- | :--- |
| **OS 부팅 및 DB 저장** | **EBS** | 지연 시간이 짧고 빠른 로컬 성능 제공 |
| **여러 서버 간 파일 공유** | **EFS** | 다수의 서버에서 동시 접근 가능한 NFS 방식 |
| **정적 이미지/영상 서빙** | **S3** | 고유 URL을 통한 웹 배포 및 대용량 처리에 최적 |
| **데이터 백업 및 로그** | **S3** | 저렴한 비용으로 무제한 확장과 높은 내구성 보장 |

---

### 5.3 Amazon EBS & EFS 상세 비교

#### 5.3.1 Amazon EBS (Elastic Block Store)
* **특징:** EC2에 부착하는 가상 하드디스크. 인스턴스 종료 시에도 데이터 유지.
* **유연성:** 중단 없이 용량 및 성능(IOPS) 확장 가능. AZ(가용 영역)에 종속됨.
* **볼륨 타입:** 
    * `gp3`(범용), `io2`(고성능 DB), `st1/sc1`(대용량 백업/저비용 HDD)
* **백업:** **스냅샷(Snapshot)** 기능을 통해 특정 시점 복구 및 다른 AZ로 복제 가능.

#### 5.3.2 Amazon EFS (Elastic File System)
* **특징:** AWS 관리형 NFS 서비스. 서버 수백 대가 동시에 접근 가능.
* **확장성:** 파일 저장 시 자동으로 용량이 늘어나고, 삭제 시 줄어드는 탄력적 구조.
* **가용성:** 멀티 AZ 지원으로 특정 AZ 장애 시에도 높은 안정성 보장.

---

### 5.4 Amazon S3 (Simple Storage Service)
* **개념:** 객체 단위로 저장하는 대용량 무제한 클라우드 드라이브.
* **구성:** `버킷(폴더)` ➔ `객체(파일)` ➔ `키(경로)`.
* **내구성:** `99.999999999%` 보장. 3개 이상의 AZ에 자동 복제.
* **스토리지 클래스 (비용 최적화):**
    * **Standard:** 고성능, 자주 사용하는 데이터.
    * **IA (Infrequent Access):** 접근 빈도는 낮으나 빠른 응답이 필요할 때.
    * **Glacier:** 아카이브(장기 보관)용, 비용이 매우 저렴함.

---

### ⚖️ 핵심 비교 요약

| 항목 | Amazon EBS | Amazon EFS | Amazon S3 |
| :--- | :--- | :--- | :--- |
| **저장 방식** | 블록 (Block) | 파일 (File) | 객체 (Object) |
| **OS 설치** | 가능 | 불가 | 불가 |
| **서버 공유** | 불가 | 가능 | 가능 (URL) |
| **용량 확장** | 수동 확장 | 자동 확장 | 자동/무제한 |
| **가용성** | 단일 AZ | 멀티 AZ | 멀티 AZ |
